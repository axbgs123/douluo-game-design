# 未定之书

《斗罗大陆》第一部背景的本地单人文字 RPG。玩家从六岁武魂觉醒开始，实时决定主角行动；正文采用贴近主角感受的第三人称限知视角。规则程序结算成长、时间、战斗和世界变化，DeepSeek 理解复杂行动、维护剧情记忆，并把确定结果写成小说。

## 已完成范围

- 三选一随机开局、无限重抽、自定义姓名、具体家庭与势力归属，以及唐三觉醒前后 20 年出生窗口；每组三张至少有一名稀有或传奇角色。
- 平民、上三宗亲传、封号斗罗子嗣、皇室旁系、隐世宗门少主、地下势力、反派余脉和保留记忆的穿越者等开局路线。
- 选定角色后再抽取人生目标与性格底色；目标可反复重抽或自定，情境题会随身份、已知身世和当前性格改变。
- 武魂、先天魂力、成长进度、瓶颈、伤势、疲劳、物品和金钱。
- 地点连接与旅行，NPC 在视野外移动、改变目标、结交或敌对。
- 可调查、介入和错过的动态事件；只有能追溯到关键人物、势力或地点的玩家因果链，才可能改写原作历史节点。
- 50 名以上重要人物、20 个以上势力、30 个以上地点、20 个以上历史节点和 50 种以上魂兽，覆盖第一部大陆、杀戮之都与海神岛阶段。
- 猎魂八阶段：需求、调查、准备、旅行、追踪、战斗、吸收、后果。
- 程序回合战斗、魂环承载判定、失败伤势、死亡和魂技生成。
- 图谱化关系与地图、时间轴任务，以及承诺、线索、计划、修炼需求、悬赏和世界消息。
- 学院、课程、宗门、拜师、势力声望与重要人物冲突。
- 隐藏传承发现、独立体系修炼、能力解锁、炼制和体系成长。
- 玩家与重要人物均支持符合身份、关系和势力资源的有代价复生。
- 主动结束、死亡、目标完成、成神或时间线结束的周目结算。
- 传承点消费、永久强化、图鉴、遗物携带和下一轮随机权重偏好。
- DeepSeek 长期摘要、未决线索、关键选择、NPC 独立记忆和动态章节。
- 四个时代共 4000 条同人规则入库；第一部会按当前行动、地点和年份提取真正适用的规则，不把整份清单生硬塞进正文。
- 年代与设定前置校验会拦截未出现的后世技术、尚未出生的人物、无来源的外部力量和直接宣布获得高阶奖励等行动。
- “故事手记”持续整理本章梗概、未决线索、关键选择、行动后果，以及当前年代与原作连续性。
- SQLite 自动存档；DeepSeek 未配置或调用失败时使用本地叙事。

当前正式入口只覆盖第一部时代。第二至第五部连续世界、Godot 封装和美术不在本版本内。

## 本地运行

需要 Node.js 24 或更高版本。

```powershell
npm install
npm run build
npm start
```

打开 `http://127.0.0.1:8787`。

开发模式：

```powershell
npm run dev
```

网页位于 `http://127.0.0.1:5173`，规则服务位于 `http://127.0.0.1:8787`。

## 游玩方式

建议按钮与自由输入走同一套规则。常见输入包括：

- `冥想修炼`、`休息`、`找临时工作`
- `查看地图`、`前往诺丁学院`
- `调查适合当前武魂的魂兽`、`购买猎魂补给`、`寻找足迹`
- `观察弱点`、`集中攻击`、`防御并拉开距离`、`开始吸收魂环`
- `申请学院入学`、`拜师玉小刚`、`加入武魂殿`
- `打听唐三`、`调查自己的身世`、`参悟特殊体系`
- `调查失踪的采药队`、`帮助处理失踪的采药队`
- `修炼到下个瓶颈`、`等待一年`

高速模式压缩操作次数和文字过程，不修改基础成功概率。

## DeepSeek

在“模型设置”中填写自己的 API Key、兼容接口地址和模型名。密钥只保存在本机 `.data/settings.json`，不会发给网页端，也不会写入 Git。

DeepSeek 会把玩家的复杂说法整理成规则动作，但无权决定成功率、胜负、魂力、物品、伤势、魂环或历史结果。系统会先检索当前场景适用的同人规则，结算后再生成正文；输出还要经过第三人称、年代、语气和长度检查。每次叙事后，它会更新玩家可知的长期摘要、未决事项和人物记忆；程序只接收受限的文本字段，不接收任何数值状态修改。

## 数据与文档

- `server/data/world.ts`：第一部世界资料源。
- `server/data/fanfiction-rules.ts`：四个时代 4000 条清单的解析、分类与检索入口。
- `server/domain/actions.ts`：成长、旅行、猎魂、战斗和自由行动规则。
- `server/domain/story-rules.ts`：场景选规、年代拦截、叙事审查和故事手记维护。
- `server/domain/world.ts`：时间推进、人物成长和原作事件。
- `server/domain/endings.ts`：周目结算。
- `docs/world-database.md`：资料库结构与信息边界。
- `docs/mvp-gdd.md`：需求访谈后冻结的设计基线。
- `docs/soul-hunting-system.md`：猎魂规则设计。
- `docs/difficulty-and-legacy.md`：难度与局外成长设计。
- `docs/release-acceptance.md`：本轮三个 10 分目标的可检查验收基线。
- `docs/interactive-fanfiction-rules.md`：联网调研后冻结的第三人称、玩家能动性与原作因果规则。
- `docs/douluo1-fanfiction-1000-checklist.md` 至 `docs/douluo4-fanfiction-1000-checklist.md`：四个时代的同人创作规则源。
