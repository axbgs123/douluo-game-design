# 原著时间线分支结算

## 目标

原著提供世界规则、人物惯性与重要事件的初始条件，不是无法改变的录像。玩家真实改变关键人物、势力、地点、权限或资源后，后续事件必须从当前世界状态重新结算。

## 因果链

每条玩家影响保存发生日期、地点、受影响人物、受影响势力、领域、强度与有效期。同一行动的重复记录会合并；多条影响采用递减叠加，不做无上限求和。原著节点只计算仍有效且具有直接人物、势力、制度或短期地点连接的影响；无关的全局“世界偏差”不能改写事件。

当关联影响没有越过节点惯性时，事件仍会发生，但公开消息会注明部分参与条件已经改变。当影响越过门槛时，程序按当前条件形成三类分支：

- 延后：核心参与条件仍存在，但准备、权限、资源或关系已经不足。事件进入新的日期后再结算。
- 替代：人物和势力仍在活动，但阵营、资源或利益结构已改变，形成不继承原结果的替代行动。
- 取消：关键参与者死亡、失去活动条件，或核心组织与地点条件已经失效，原事件不再发生。

## 分支后果

分支结算不是一条提示文字。程序会同时：

1. 写入结构化 `canonTimelineBranches` 记录。
2. 更新仍存活参与者的当前目标并废止旧行动计划。
3. 生成可继续介入的历史分支事件。
4. 更新历史影响指标。
5. 以45%强度生成分支因果，只在三年内向具有直接依赖的节点继续传播。

因此，玩家改变唐三的早期入学条件后，紧邻的入学、拜师节点会重新判断；数年后的史莱克聚首只有在中间状态继续提供充分因果时才会改变，不能因为共享“唐三”一个名字便自动感染整条主线。

## 显式事件依赖

只靠“共享人物”无法判断真正前置。当前在`server/data/canon-event-dependencies.ts`登记91条分类关系：

- 前置按原条件发生：后继继续保留原著惯性。
- 前置延后：后继先进入等待，在前置新日期真正发生后再从新条件结算。
- 前置被替代：后继不得继承原结果，必须形成替代行动。
- 前置被取消：依赖该条件的原定后继一并取消，留下的资源、责任和敌意另行重组。

并非所有先后关系都是硬前置。`catalysts`只影响发生条件与规模，`siblings`表示同一行动的并列结果，`observationRoute`只决定玩家为何在场；这些关系缺失时不得直接取消世界事件。

依赖传播严格按时间向后。后继事件为了等待前置而生成的因果，不能反向把前置本身改成替代或取消。同日事件按依赖深度排序，先结算前置再结算后继。

## 信息边界

远方分支可以在隐藏世界正常结算，但只有公开事件、玩家在场、可靠事件情报或真实传播链满足可观察条件时，才会进入消息、前台原作因果、AI提示词和向量召回。仅仅认识参与者不等于能够实时知道其远方行动。

## 存档

Schema 37为旧存档补充时间线分支账本，并为旧因果足迹推断领域、有效期和传播深度，不删除已有玩家行动。旧存档下一次触发原著节点时会按分域与衰减后的有效影响生成分支。
