# 四时代发布验收基线

本页只记录可以观察或自动检查的行为。“自动测试通过”不等于已完成真实模型质量、长篇内容量或商业发行验收。

## 1. 四时代共同基线

- 新游戏明确选择斗一、斗二、斗三或斗四，存档持久化 `era`。
- 四个时代分别使用 0、10000、20000、30000 附近的绝对原作纪年，但时间线结束按本时代相对年数计算。
- 候选出身、武魂、人生目标、地图、人物、势力、地点和事件符合所选时代。
- 未出生/已死亡人物、未成立/已消亡势力、未开放地点以及未来技术不得进入当前世界或正文。
- 玩家从角色候选、塑造、觉醒、人生目标进入正式行动；旧存档可迁移到 Schema 14。
- 有效结算可选择在同一槽位推进下一时代，自动保存旧世终章检查点；新角色继承可疑史料和因果回声，不复制魂力、魂环或装备战力。四时代独立入口继续保留。
- 自由文本先解析为规则动作，再由程序原子结算，最后生成叙事；失败请求不得留下半写入状态。
- `revision` 阻止并发覆盖，`requestId` 保证重试幂等，动作收据可解释结算依据。
- 隐藏身份、未观察事件和 NPC 私有信息不发送给前端或叙事模型。
- 承诺只有出现规则证据后才能完成；关键原作事件只有玩家因果足迹足够时才可偏移。

## 2. 分时代玩法基线

| 时代 | 必须通过的行为 |
|---|---|
| 斗一 | 猎魂八阶段、独立武魂魂环账本、战术战斗、需要岗位/信任/训练/准备/冷却证据的多人连携、固定搭档跨战斗熟练度/失败复盘/战术分支、学院/宗门/势力路线、原作事件惯性与可追踪偏移 |
| 斗二 | 魂导理论、材料、制作、失败损耗与认证可持久化；魂灵在 10005 前仅为前置研究、10005 起限史莱克试验、10012 起开放传灵塔试验 |
| 斗三 | 斗铠图纸、契合、分级材料、九部件、失败损耗和成套加成；机甲模拟、五色分级资质、专属购置、能量与战斗效果 |
| 斗四 | 天罗星与天斗星开篇地理正确；联邦客运和自有星舰分流；七岁基础训练、三年见习与十二年正式岗位门槛、精神能力、持证可信舰员、舰船资源、星际风险、行星探索，以及与模拟训练分账的真实航时、军功和军衔晋升 |

时代专属行动必须同时满足年代、地点、身份/机构、资源和前置进度。普通旅行指令不得绕过星舰航行条件，叙事审校也不得把未来科技当成文字自由度放行。

## 3. 小说与交互基线

- 正文采用第三人称限知，不替玩家作重大关系、阵营、生死或道德决定。
- 模型只能使用当前场景、玩家已知事实、最近经历、长期摘要、未决线索和相关 NPC 记忆。
- 模型调用记录职责、令牌、延迟和失败状态以支持预算验收；不得把 API Key、完整提示词、推理过程或生成正文写入遥测表。
- 规则结果与叙事结果分离；模型不得赠送力量、物品、胜利、关系或历史改写。
- 普通行动与关键节点使用不同篇幅目标；失败稿最多定向重写，不无限消耗额度。
- UI 能展示角色、武魂、关系、任务、地图、世界状态以及当前时代专属系统。
- 常驻“时代”页签在专属状态尚未初始化时也必须可见，并提供可点击的第一步；按钮与自由文本走同一规则结算。
- 桌面端为当前视觉目标；窄屏保证基本可操作，不作为最终美术验收。

## 4. 自动验证门槛

发布分支必须全部通过：

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
npm run quality:long-session
npm audit --omit=dev
```

2026-08-24 基线：10 个测试文件、147 项单元/集成测试、5 条 Playwright 浏览器流程、生产依赖漏洞 0 项。

测试至少覆盖：四时代创建及序列化长会话、长局账本/正文覆盖与 NPC 记忆、同槽位世代继承、累积谱系、家庭档案只作历史证据且不复制战力、历史权益核验和终章检查点、Schema 迁移、时代人物/势力/地点隔离、技术年代拦截、魂灵/魂导器、斗铠/机甲、星舰、战斗、猎魂与有能力证据的小队岗位和多人连携、固定搭档连携熟练度/失败复盘/战术分支和跨战斗效果、见证者/势力地方口碑传播、分时代媒体机构/编辑立场/延迟/拒稿/覆盖/可信度/交叉核验、证据化媒体更正、秘密行动与化名隔离、未成年关系门禁、成年伴侣/婚姻/家庭的双方同意和冷静期、年龄适配工作、雇主关系、经济流水、区域供需价格、经营盈亏、跨区域运输合同、分阶段专属机构事务证据与贡献晋升、能力匹配或显式选择的宗门外勤/情报/支援分支及失败证据门禁、幂等和版本冲突、隐藏知识、事件观察、承诺证据、数据库事务及浏览器时代选择。

## 5. 仍需人工验收

- 使用用户自行配置的真实 DeepSeek 兼容模型，进行四时代各至少一段多轮小说体验和费用记录。
- 检查长篇正文的人物声音、重复率、事实连续性、节奏和上下文增长。
- 以用户本地原著资料逐项抽查人物年份、事件日期、术语与技术开放节点；原著文本不得提交。
- 检查桌面分辨率、窄屏、错误提示、断网、模型限流和服务重启恢复。
- 公开发布前完成版权、平台规则、隐私与密钥处理审查。
