# 四时代发布验收基线

本页只记录可以观察或自动检查的行为。“自动测试通过”不等于已完成真实模型质量、长篇内容量或商业发行验收。

## 1. 四时代共同基线

- 新游戏明确选择斗一、斗二、斗三或斗四，存档持久化 `era`。
- 四个时代分别使用 0、10000、20000、30000 附近的绝对原作纪年，但时间线结束按本时代相对年数计算。
- 候选出身、武魂、人生目标、地图、人物、势力、地点和事件符合所选时代。
- 未出生/已死亡人物、未成立/已消亡势力、未开放地点以及未来技术不得进入当前世界或正文。
- 玩家从角色候选、塑造、觉醒、人生目标进入正式行动；旧存档可迁移到 Schema 32。
- 有效结算可选择在同一槽位推进下一时代，自动保存旧世终章检查点，并累积带年份、来源、可信度、证据与核验状态的时代间年表；系统推演假说必须明确标为非原著事实。新角色继承可疑史料、具名家庭旁支和因果回声，不复制魂力、魂环、遗传能力或装备战力。旧机构必须经过当代权属调查、付费主张与听证，最多取得档案/名称沿革有限权利；经营必须另行投资新主体。四时代独立入口继续保留。
- 自由文本先解析为规则动作，再由程序原子结算，最后生成叙事；失败请求不得留下半写入状态。
- 程序结算后、叙事模型调用前必须通过 `narrative-logic.v1`：主角欲望、信息来源、权限、资源、固定后果、参与者反应义务、场景人数和至少一项可追踪状态变化缺失时，不得调用模型或进入生成重试。
- `revision` 阻止并发覆盖，`requestId` 保证重试幂等，动作收据可解释结算依据。
- 隐藏身份、未观察事件和 NPC 私有信息不发送给前端或叙事模型。
- 承诺只有出现规则证据后才能完成；关键原作事件只有玩家因果足迹足够时才可偏移。

## 2. 分时代玩法基线

| 时代 | 必须通过的行为 |
|---|---|
| 斗一 | 猎魂八阶段、独立武魂魂环账本、战术战斗、需要岗位/信任/固定成员训练/准备/冷却证据的双人连携与三至七人战阵，重复岗位须精确匹配人数；固定组合跨战斗熟练度/失败复盘/战术分支、学院/宗门/势力路线、原作事件惯性与可追踪偏移 |
| 斗二 | 魂导理论、材料、制作、失败损耗与认证可持久化；魂灵在 10005 前仅为前置研究、10005 起限史莱克试验、10012 起开放传灵塔试验 |
| 斗三 | 斗铠图纸、契合、分级材料、九部件、失败损耗和成套加成；机甲模拟、五色分级资质、武魂专属设计、所有者与黑级唯一绑定、合规购置、能量与战斗效果；初级升灵台名额/费用/四环以下门禁、常规与暴动期团队、同年两次限制、百秒守护、待吸收灵力散失、虚拟遭遇、脑波冲击、求救退出与延迟结算；中级实名入门卡、七环以下门禁、斗铠师年度福利与增强遭遇；高级层要求斗铠师登记、传灵塔任务点/贡献、一次性授权、明确风险同意和服务费，年度半价权益可核销，真实核心层保持独立封锁；斗铠设计、机甲设计/制造/维修、锻造第二职业的实训作品、逐级认证、材料消耗、失败退件与付费委托 |
| 斗四 | 天罗星与天斗星开篇地理正确；联邦客运和自有星舰分流；七岁基础训练、三年见习与十二年正式岗位门槛、精神能力、持证可信舰员、舰船资源、星际风险、行星探索；现役人员须经舰队参谋部述职、至少三十天且覆盖三类模块的入舰培训，再按精神感知/模拟记录或实战/损管证据分配至舰队参谋部或龙王级护卫舰作战部；模拟训练、真实航时、军功和军衔继续分账 |

时代专属行动必须同时满足年代、地点、身份/机构、资源和前置进度。机构长任务在中段触发主审与独立复核派系冲突：共同协调要求分别会谈和至少两阶段证据；明确站队会持久改变派系信任并保留贡献扣减，未处理冲突不得最终交付。派系信任、影响力与政治历史必须跨任务、存档刷新持久化，并改变后续复核人的初始信任。普通旅行指令不得绕过星舰航行条件，叙事审校也不得把未来科技当成文字自由度放行。

## 3. 小说与交互基线

- 正文采用第三人称限知，不替玩家作重大关系、阵营、生死或道德决定。
- 模型只能使用当前场景、玩家已知事实、最近经历、长期摘要、未决线索和相关 NPC 记忆。
- 模型调用记录职责、令牌、延迟和失败状态以支持预算验收；不得把 API Key、完整提示词、推理过程或生成正文写入遥测表。
- 规则结果与叙事结果分离；模型不得赠送力量、物品、胜利、关系或历史改写。
- 长篇旧事必须通过本地向量记忆按当前行动检索，召回只能包含玩家已知事实且不得覆盖当前状态、程序结算或 NPC 知识边界；回溯后不得召回未来分支。
- 全局斗罗知识必须覆盖人物性格与人生阶段、关键关系、势力利益、地点、重要事件和魂兽生态，并按时代、年份与玩家已知范围过滤；重要事件保持惯性但可被充分玩家因果改写，普通地方世界持续自主变化。
- 世界基本逻辑必须独立于原著事实，覆盖高天赋目击、复测、培养争夺、资源倾斜、秘密传播、监视、绑架和暗杀升级条件；高天赋必须改变利益反应，但不得直接保证拜师、好感或无条件奖励。
- 每次正文模型调用、审校重试和正文重写前必须重新检索三层向量上下文并记录实际召回数量；世界逻辑为空或检索失败时不得调用模型。
- 正式行动必须维护六阶段卷级故事状态、压力、回报承诺和剧情证据；阶段只能由真实程序结果推进，不得伪造失败、胜利、敌人、资源或玩家决定。
- 当世具名NPC必须维护欲望、责任、信息边界、权限、资源、行动与期限；移动必须服从路线和许可，完整计划不得直接泄露给玩家。
- 动态事件必须按时代和年份过滤；斗二魂导/魂灵、斗三升灵台/斗铠/机甲、斗四星舰/航时/外星生态事件不得跨时代出现。事件到期、被拒绝或介入失败后必须留下事件专属的供需、治安、伤亡、制度、关系、势力或生态后果，并限制自动后续事件深度。
- 浏览器测试必须使用15173/18787隔离端口和临时数据库，禁止复用5173/8787用户服务或清理真实存档。
- 普通行动与关键节点使用不同篇幅目标；失败稿最多定向重写，不无限消耗额度。
- 非悬疑行动不得被模型强行改写成解谜：普通修炼、入学、生活、交友、交易和胜利可以直接兑现成长、资源、待遇、关系与情绪回报。
- UI 能展示角色、武魂、关系、任务、地图、世界状态以及当前时代专属系统。
- 局外召唤区必须直接提供召唤记录、武魂仓库、身世仓库和遗物仓库；遗物卡显示效果、触发条件和每局次数。
- 可抽武魂池不得少于300种且名称唯一；身世专属召唤每抽必出紫色以上并包含七彩档，金/红/七彩分别具有10/30/60抽独立保底；武魂/身世/遗物仓库必须支持展开、收起和按稀有度筛选。
- 已装备身世创建对应时代新游戏时必须直接采用该身份并进入角色塑造，不得再次要求身份三选一；修复前已生成的同类候选存档在加载时也必须迁移；未装备身世的随机开局仍保留候选选择。
- 召唤获得的武魂必须立即永久解锁并可无限次指定新开局；选定角色时不得扣减次数，旧仓库条目载入后也升级为无限使用。
- 双生或三生武魂必须品质一致；遗物可以明显强于常规能力，但必须有每局次数、触发条件或主动预备，并且不能复活、改写胜负或跳过时代/机构权限。
- 常驻“时代”页签在专属状态尚未初始化时也必须可见，并提供可点击的第一步；按钮与自由文本走同一规则结算。
- 桌面端为当前视觉目标；窄屏保证基本可操作，不作为最终美术验收。
- 推荐选项分别覆盖成长/资源、关系/势力、秘密/风险；不得使用泛化占位按钮、未公开的隐藏武魂或玩家尚未认识的原著人物。异常觉醒结果必须引发符合目击者利益与权限的具体反应。

## 4. 自动验证门槛

发布分支必须全部通过：

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
npm run quality:long-session
npm run security:release
npm audit --omit=dev
```

GitHub CI 对每次 push 和 pull request 执行同一组类型、测试、构建、四时代长局、安全扫描、生产依赖审计与浏览器门槛；本地结果不能替代远端状态。

2026-08-25 基线：16 个测试文件、217 项单元/集成测试、28 条 Playwright 浏览器流程定义、被跟踪文件发布安全门禁通过、生产依赖漏洞 0 项。

## 5. 仍需人工验收

- 使用用户自行配置的真实 DeepSeek 兼容模型，进行四时代各至少一段多轮小说体验和费用记录。
- 检查长篇正文的人物声音、重复率、事实连续性、节奏和上下文增长。
- 以用户本地原著资料逐项抽查人物年份、事件日期、术语与技术开放节点；原著文本不得提交。
- 检查桌面分辨率、窄屏、错误提示、断网、模型限流和服务重启恢复。
- 公开发布前完成版权、平台规则、隐私与密钥处理审查。
