Schema 48只回填旧存档已经发生过的等价节点：旧诺丁事件映射入学/相识，旧杀戮之都记录映射蓝银皇觉醒与入城，已成立唐门映射筹备/宗族聚会，斗三双目标袭击与斗四深红入侵补齐共同父事件。不会把尚未发生的未来节点提前写入存档。

Schema 49新增原著事件干预项目。角色必须先有亲历、告知、可靠调查、公开消息或已经揭示的穿越时间线记忆，才能以具体事件为目标立项；调查只形成事件情报，不产生历史影响。计划需要至少两项情报、一条可接近路线与两项真实准备，资源准备会扣除魂币、演练会增加疲劳，取得NPC或势力支持必须使用现有信任与隶属关系。实际执行按情报、路线、准备、支持、人物能力、难度和事件惯性结算；只有程序确认执行结果后才写入精确指向目标节点的因果足迹，随后仍需独立核验。错过原定日期的未执行计划会失败，不能把准备冒充改史。

事件依赖分类也开始参与运行：硬前置缺失继续触发延后/替代/取消；玩家改变催化节点后，相关后继节点的惯性会下降，但催化缺失本身不等于事件必然取消；并列结果和观察路线不会被误当作硬前置相互取消。世界面板显示干预项目的情报、路线、准备、阶段、目标日期与下一步。

Schema 50处理全局审查中最先断裂的行动—人物—正文链。父母、原创老师、导师候选与同辈关系现拥有当前目标、责任、信息边界、权限、资源、下一步行动、位置和最近结果，并随世界时间推进；玩家可以直接使用父亲、母亲、老师等自然称谓。吃饭、家务、帮忙、读写、常识学习和具名同辈切磋有独立结算。指定对象调查不再随机替换成无关原著人物；学院材料、考核和报到必须由对应行动推进；猎魂行动不再误判为猎取魂环；动态事件唯一锁定名称并禁止隔空介入；压倒性战力差不再保留百分之一击杀漏洞。

同一Schema还收紧原著干预：执行只在节点前120日开放，必须身处目标地点并完成实地路线，不同准备类别不可重复刷强度，组织支持需要贡献或实际职位，物资成本与事件惯性挂钩。被规则阻止的关键词不再生成能力证明或阶段兑现。正文连续失败时，逻辑预检错误仍会停止提交；单纯模型/审校失败则采用程序安全正文并记录AI正文未采用，避免行动消失。设置页分别显示模型传输失败和正文审校拒绝；回溯后旧召回记录不再冒充当前存档样本。人物与关系向量移除了通过否定句反向提示未来姓名、身份和关系结果的内容。

Schema 51分离原著时间精度与程序调度。现有事件的年份继续作为原著或原著归纳锚点；只有明确标注`dayProvenance=原著`的日序才能对外显示为原著日期。此前第20日、第120日等项目内日序统一视为游戏估算，向量和干预面板只显示“具体日序未核实”。72个只有年份的节点会按同年硬前置、并列结果和已核对的原文章节先后形成内部调度：硬前置必定早于后继，并列结果可以同日；调度值不进入原著事实文本。日序不清的事件保留推测窗口，若其成立条件未被玩家改变，默认在窗口末端触发，给玩家完整准备时间；若参与者、关系、资源、地点或势力条件已被改变，该事件转入延后、替代或取消分支，不再强制套用原窗口。旧存档因默认第1日提前触发、且没有玩家因果或可靠情报支撑的年份级事件会被撤回并等待新调度。

## 1. 项目定位

## 4. 角色创建与状态流

```text
candidate_selection
  → character_shaping
  → awakening
  → life_goal_selection
  → playing
  → ended
```

3. 可锁定栏位、刷新和改名。

6. 看清觉醒结果后选择或自定人生目标。
7. 进入正式自由行动。

## 5. 数据与时代隔离

`GET /api/world/catalog/stats` 是资料数量的唯一权威来源。当前为68份斗一出生档案、299个可觉醒武魂、96个势力与80个地点。原文项、归纳项和原创项必须分开展示与审校；其他目录数量后续增删资料时应重新调用接口，不要手工推算。

本轮同时加入九类“原著留白改写”身份（包括圣魂村猎户邻居、比比东秘密养子、宁荣荣幼年婚约候选等）。这些身份只借用可成立的相邻关系：同村不自动成为朋友，收养不自动获得亲情或继承权，婚约不自动产生爱情且双方都可拒绝。人生目标刷新会保留锁定栏位、排除重复值，并按武魂战斗/辅助路线与性格倾向加权。

觉醒归属已改为通用势力规则：宗门、家族、皇室辖区由所属势力主持觉醒并优先评估，普通公共觉醒才由地方武魂殿负责；先天满魂力当日进入最高优先。若武魂与可达的原著重要人物相同或直接相关，会通知本人复核，例如七宝琉璃宗内觉醒七杀剑会通知尘心，但不会自动保证收徒或无条件庇护。

关键隔离规则：

- 人物同时受 `birthYear`、`deathYear` 与时代兼容判定控制。
- 没有死亡年份的普通旧时代人物不会自动活到后世；明确长寿的命名魂兽例外。
- 势力通过统一的时代可用函数判断成立、存续和消亡。
- 地点与地图点按时代过滤，候选页和正式地图使用同一规则。
- NPC、势力、地点、原作事件和技术名词都必须通过年代检查。
- 斗四跨星球普通旅行不会绕过舰船、船员、燃料、补给和船体要求。

## 6. 行动事务与叙事流水线

```text
请求版本/幂等检查
  → 年代、地点与资源前置检查
  → AI 语义整理
  → 程序在内存副本中结算
  → 编译并审计欲望/信息/权限/资源/反应/连续性逻辑包
  → 相关世界规则与知识检索
  → AI 根据确定结果生成正文
  → 人称/年代/知识/文风审校
  → 原子写入存档、事件和动作收据
```

- 客户端提交 `revision`，过期版本返回冲突，不静默覆盖。
- `requestId` 让网络重试返回同一结果，避免重复扣资源或推进时间。
- 结算或叙事失败不留下半写入存档。
- 每次行动保存可见规则收据，便于解释为什么成功、失败或被阻止。
- 单次服务器请求最多生成 4 稿，客户端只进行一次完整重发；不无限消耗额度。
- 缺少 Key、规则拒绝和主动取消不会自动重试。

叙事器只能看到玩家可知的场景资料、长期摘要、未决事项、最近经历和相关 NPC 记忆。远方未观察事件、隐藏身份和 NPC 私有状态不会提前进入前端或模型上下文。

## 10. HTTP API 摘要

- 检查点：`GET/POST /api/games/:id/checkpoints`、`POST .../:checkpointId/restore`

- 剧情：`action`、`action/stream`、`action/rewrite`、`speed`、`end`

- 地图标点：`POST /api/games/:id/map/pins`、`DELETE /api/games/:id/map/pins/:pinId`
