## 1. 项目定位

这是一个本地运行的单人网页互动小说 RPG，已提供斗一《斗罗大陆》、斗二《绝世唐门》、斗三《龙王传说》和斗四《终极斗罗》四个独立新游戏入口。玩家从六岁武魂觉醒开始，以自由文本控制原创主角。

职责边界：

- 程序决定时间、魂力、成长、战斗、伤势、资源、关系、NPC 状态与历史结果。
- DeepSeek 把复杂输入整理为规则动作，并把程序结果写成第三人称限知小说。
- AI 不能修改数值、胜负、物品、关系或历史，也不能泄露角色不知道的秘密。
- 只有玩家真实留下的因果足迹才能改变关键原作事件。

当前是功能完整度优先的网页原型，没有正式美术。不要把“自动测试通过”表述为内容、美术、版权或真实模型体验已经最终验收。

## 3. 四时代入口与专属系统

| 时代 | 基准年 | 专属内容 |
|---|---:|---|
| 斗一 | 0 | 完整猎魂链、学院/宗门/势力路线、战术战斗和原作事件干预 |
| 斗二 | 10000（霍雨浩十一岁离府求学锚点） | 魂导器理论、材料、制作、认证；分阶段开放的魂灵研究与契约 |
| 斗三 | 20000 | 斗铠图纸、契合、分级锻造材料、九部件与套装；机甲分级资质、专属购置、能量与战斗 |
| 斗四 | 30000 | 天罗星/天斗星、联邦客运、星舰指挥认证、参谋部述职、满月入舰培训与能力证据分岗、可信船员、舰船、燃料/补给/船体、行星探索、军功/真实航时/军衔与高风险战区准入 |

四时代是独立开局，不是一个存档自动跨越四万年的连续继承模式。相对游戏年用于终局判断，绝对原作年用于人物、势力、地点、事件与技术开放。

正式剧情右侧有常驻“时代”页签。斗一提供修炼、入学和猎魂入口；斗二提供魂导学习/购料/制作与魂灵流程；斗三提供斗铠和机甲入口；斗四提供参谋部述职、入舰培训、岗位评估、指挥训练、考核、招募与项目舰入口，并展示培训天数和分岗结果。自由文本仍与这些按钮共用同一套规则。

### 斗二魂灵时间门

本地原著抽查确认并落实为规则：

- 10005 年以前：只能接触魂灵前置研究，不能签订成熟魂灵。
- 10005–10011 年：仅允许史莱克内部试验路线。
- 10012 年起：传灵塔首批试验路线开放。

这不是只写在提示词里的约定；动作结算与叙事年代审校都会阻止提前使用。

## 4. 角色创建与状态流

```text
candidate_selection
  → character_shaping
  → awakening
  → life_goal_selection
  → playing
  → ended
```

1. 选择时代、性别、难度和可选种子。
2. 一次生成三名角色，只公开出身、背景与觉醒征兆。
3. 可锁定栏位、刷新和改名。
4. 选定后抽取性格底色并回答身份相关情境题。
5. 完成武魂觉醒，公开单/双生/三生武魂与先天魂力。
6. 看清觉醒结果后选择或自定人生目标。
7. 进入正式自由行动。

斗一出生组合数为 36,000；后世使用各时代的精选出身、家庭气氛和居住参数组合。双生和三生武魂各自拥有独立修炼、魂环与切换状态，副武魂不会无条件叠加战力。

## 5. 数据与时代隔离

`GET /api/world/catalog/stats` 是资料数量的唯一权威来源。2026-08-24 隔离数据库实测基线为：36,000 个斗一出生组合、159 个可觉醒武魂、159 个重要人物/智慧魂兽、175 个实力节点、77 个势力、69 个地点、105 个历史事件、212 个魂兽模板和四时代共 4,000 条同人规则。后续增删资料时应重新调用接口，不要手工推算。

关键隔离规则：

- 人物同时受 `birthYear`、`deathYear` 与时代兼容判定控制。
- 没有死亡年份的普通旧时代人物不会自动活到后世；明确长寿的命名魂兽例外。
- 势力通过统一的时代可用函数判断成立、存续和消亡。
- 地点与地图点按时代过滤，候选页和正式地图使用同一规则。
- NPC、势力、地点、原作事件和技术名词都必须通过年代检查。
- 斗四跨星球普通旅行不会绕过舰船、船员、燃料、补给和船体要求。

原著全文位于用户本机被忽略的 `source-materials/`，只可用于事实核查，不得提交、复制进产品数据或随构建发布。

## 6. 行动事务与叙事流水线

```text
请求版本/幂等检查
  → 年代、地点与资源前置检查
  → AI 语义整理
  → 程序在内存副本中结算
  → 相关世界规则与知识检索
  → AI 根据确定结果生成正文
  → 人称/年代/知识/文风审校
  → 原子写入存档、事件和动作收据
```

- 客户端提交 `revision`，过期版本返回冲突，不静默覆盖。
- `requestId` 让网络重试返回同一结果，避免重复扣资源或推进时间。
- 结算或叙事失败不留下半写入存档。
- 每次行动保存可见规则收据，便于解释为什么成功、失败或被阻止。
- 单次服务器请求最多生成 4 稿，客户端只进行一次完整重发；不无限消耗额度。
- 缺少 Key、规则拒绝和主动取消不会自动重试。

叙事器只能看到玩家可知的场景资料、长期摘要、未决事项、最近经历和相关 NPC 记忆。远方未观察事件、隐藏身份和 NPC 私有状态不会提前进入前端或模型上下文。

## 7. 通用玩法状态

已实现：

- 魂力、瓶颈、长程修炼、年龄和季节。
- 货币、职业工资、负重、仓储、债务、悬赏和基础经营。
- 学院、课程、拜师、宗门、势力声望与犯罪热度。
- 猎魂八阶段、栖息地筛选、最后一击、承载、失败伤势和魂技生成。
- 观察、防守、距离、攻击、魂技、撤退和可恢复的战术战斗；强攻/防护/控制/治疗/侦察岗位可组成四种双人连携和三种三人阵型，均要求互补岗位、关系信任、共同训练证据、准备回合、协同消耗和冷却。固定组合拥有跨战斗训练档案、熟练度、疲劳失败复盘与达标战术分支；三人阵型还要求同一组三人先达到 15% 熟练度，实战不会泛化为全队加成。
- NPC 自主移动、目标变化、NPC-NPC 关系与情景记忆。
- 公开履约、重大事件介入和违法行为会形成隐藏传播记录，先经现场见证者与共同势力关系延迟转化为地区口碑，再依时代进入城市公报、报刊与魂导广播、大陆魂导传媒或联邦公共信息网；每家机构拥有独立责任编辑，刊发标注责任人、来源信任、机构信誉、来源、可信度和覆盖范围。公开澄清必须先登记核验、完成后续调查并提交证据，责任编辑会留下签发更正与信任变化，旧消息不会被删除。秘密无人行动不传播，地方化名与真名不自动合并。
- 年龄与岗位约束的日常工作、随熟练度变化的工资、可积累的本地雇主关系，以及收入、采购、存取款、借贷、还款和经营投入流水。
- 成年伴侣、婚姻与家庭采用共同经历阈值、双方明确同意、七天冷静期、稳定共同生活、住所资金和长期家庭计划；未成年人只进入年龄适配的友情与成长关系。家庭谱系可进入终局与后世档案，但不复制武魂、等级、资产或战斗能力。
- 星舰船员的驾驶、导航、轮机、战术与医疗岗位需要对应履历证据；舰桥协同、岗位轮值和损管演练独立于个人模拟训练，保存参与岗位与复盘记录，并通过协同熟练度降低远航事故风险。
- 区域市场之间可承接运输合同：先垫采购款、占用随身或星舰运力，亲自抵达后再按货封完整度和期限结算盈亏；普通客运船票不能夹带跨星球商业货运。
- 动态事件、可观察世界消息、原作事件惯性与玩家因果偏移。
- 任务、承诺、线索、计划、修炼需求与证据化完成条件。
- 机构事务不是单次口头交差：通用宗门按武魂能力或明确选择进入外勤、情报、支援 4 阶段分支；斗二魂导器合规研制为 5 阶段，斗三传灵塔审计与战神巡防各 4 阶段，斗四舰队值勤为 5 阶段、星际学院考核为 4 阶段。每阶段只接受该阶段开始后的成功行动收据；失败尝试和代价保留但不算通过，全部登记后才发贡献与报酬。
- 死亡、有限条件复生、主动结束、目标完成、成神与时间线结算。
- 传承点、永久强化、遗物、图鉴与下局随机偏好。

## 10. HTTP API 摘要

- 健康/资料：`GET /api/health`、`GET /api/world/catalog/stats`
- 模型设置：`GET/POST /api/settings/deepseek`；安全用量遥测：`GET /api/settings/deepseek/usage`（可按 `gameId` 过滤）。
- 存档：`GET/POST /api/games`、`GET/DELETE /api/games/:id`
- 检查点：`GET/POST /api/games/:id/checkpoints`、`POST .../:checkpointId/restore`
- 创建：`reroll`、`select`、`shaping/reroll`、`shaping/complete`、`awaken`、`life-goal`
- 剧情：`action`、`action/stream`、`action/rewrite`、`speed`、`end`
- 局外：`GET /api/meta` 与 `purchase`、`equip`、武魂图鉴抽取/装备/开关
- 地图标点：`POST /api/games/:id/map/pins`、`DELETE /api/games/:id/map/pins/:pinId`

## 12. 仍未完成的人工验收与风险

## 14. Git 与安全注意事项

- 默认开发分支使用 `codex/` 前缀；当前为 `codex/iterative-optimization`。
- 每个可独立回滚的里程碑单独提交并推送。
- `source-materials/`、`.data/`、API Key、构建产物和测试临时数据库不得提交。
- 工作区可能含用户自己的未跟踪文件；不要用 `git reset --hard`、`git checkout --` 或递归删除清理。
- 提交前至少执行 `git status --short`，确认没有密钥或原著文本进入暂存区。
