# P0 小说运行链专项审计

审计日期：2026-08-26。

本轮处理真实模型验收前仍可完成的三项P0：高频规则兜底正文的人称、自由文本核心路由优先级、三层上下文召回验收。没有配置或调用新的付费密钥。

## 修复前证据

- `server/domain/actions.ts`约有190处规则兜底正文，其中约99处源码以第一人称起草，再在写入页面前用字符串替换转成第三人称。高频修炼、休息、调查、交谈、工作、等待和失败动作也在其中。
- 自由文本的学院、导师、猎魂与交谈优先级散落在`resolveAction`长条件链中。一个输入可能同时命中“导师课程/学院课程”或“导师首环/猎魂”，但旧收据不记录被排除的候选。
- 用户现有本地数据库保存83次历史模型调用，但`context_retrievals`为0；这些历史调用发生在召回审计落地前，不能证明当前版本真实正文已经使用三层向量上下文。

## 本轮修复

| 项目 | 当前行为 |
|---|---|
| 高频兜底正文 | 修炼、瓶颈、休息、调查、具名/普通交谈、工作、等待和无法完成直接返回原生第三人称；测试在写入页面前审计原始兜底，不再允许靠事后换人称通过 |
| 核心动作路由 | `classifyCoreActionRoute`集中维护导师独立复练、导师首环帮助、正式导师、非猎杀魂环、活跃猎魂、学院申请、学院生活、导师接触和具名交谈九类候选及优先级 |
| 冲突可追踪 | `ActionResolution`与最后行动收据保存最终路由和全部候选；测试覆盖“导师首环帮助”同时命中猎魂时仍优先由导师首环路线结算 |
| 召回验收状态 | 模型用量接口新增正文检索次数、是否通过和状态。没有升级后正文样本时明确显示“未产生升级后正文样本”；原著知识或基本逻辑召回为0时显示“不完整” |
| 付费冒烟 | 四时代真实模型冒烟现在要求8轮正文成功、请求与费用不超上限，并且四个时代都留下三层正文检索通过记录，否则命令退出失败 |

## 保留边界

- 原始源码仍有低频第一人称兜底，集中在战斗、媒体、后世职业、违法、星舰等专项系统。本轮没有机械批量替换，以免破坏对白、多人“我们”或职业语境；后续按真实模型样本继续逐类原生改写。
- 当前本地数据库的0条上下文召回不表示当前代码没有检索，而表示尚未产生升级后的真实模型正文样本。只有新调用留下`narrator`召回记录后才能判断通过或不完整。
- 本轮没有真实模型密钥，因此不能宣称文风质量已经通过付费模型验收。
