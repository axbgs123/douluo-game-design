# 技术架构初稿

## 总体原则

游戏不是把全部规则交给聊天模型的纯角色扮演页面，而是“确定性状态引擎 + NPC 模拟器 + AI 叙事器”。

## 主要模块

### 浏览器界面

- 小说正文、章节和固定操作区。
- 自然语言输入和三个建议行动。
- 属性、武魂/魂技、背包、地图、关系、任务和时间面板。
- 存档、设置、API Key 与调试工具。

### 游戏状态引擎

- 新存档默认使用系统熵生成随机种子，再用固定种子生成候选角色和随机事件，既保证每局不同，也支持复盘与复现。
- DeepSeek 不参与随机抽取和结果判定。它可以把复杂自然语言整理成规则动作，程序仍负责检查前提并计算结果。
- 保存角色、NPC、地图、时间、物品、关系、任务、战斗、历史锚点和偏差状态。
- 对超出能力的自然语言行动仍建立尝试事件，由规则判定失败、耗时、风险和后果，不把玩家输入静默改写成其他行动。
- 任务表保存来源、承诺、线索、期限和自然后果，不使用统一的“完成即发奖”逻辑。
- 猎魂流程保存调查、准备、旅行、追踪、战斗、吸收和后果七阶段状态，高速模式只改变叙事与交互粒度。
- 快进采用逐事件模拟，命中死亡风险、突破、袭击、重要关系变化或历史锚点时强制中断，不能直接把起止日期之间的状态线性相加。
- 保存初始性格关键词、情境题答案、行为证据和随时间变化的人格特质；AI 只能读取人格状态，特质变化由规则层根据已发生事件提交。
- 对推荐、体系兼容和猎魂风险分别保存“世界真相”与“角色已知信息”；客户端和 AI 叙事只能读取当前角色有权知道的视图，避免模型提前泄露隐藏冲突。
- 所有持久变更都经过 schema 校验和事件日志，不从小说文本反向猜测状态。

### NPC 模拟器

- 重要 NPC 使用目标、计划、关系、记忆和资源进行较细模拟。
- 普通 NPC 和远方区域按时间批次进行低成本汇总模拟。
- 玩家造成的变化通过事件和关系网络传播。
- 每三十天批量推演 NPC 移动、目标和关系；事件拥有地点、期限、参与者和自然结局。
- 重要人物死亡后，所属势力可以按人物价值与资源付出代价尝试复生。

### 战斗引擎

- 程序计算行动是否合法、命中、伤害、控制、资源消耗、伤势和胜负。
- AI 只能在既定结果范围内生成战术过程与第三人称限知小说文本。

### AI 编排器

- 第一次短调用只整理玩家行动语义，不判断结果。
- 规则结算后，把当前场景、长期摘要、未决线索、相关人物记忆、最近十二条正文和确定结果发送给模型。
- 模型返回正文、三个建议行动和玩家可知的记忆补丁。程序只接受摘要、线索、关键选择、章节名和人物笔记，不接受数值状态修改。
- 每次请求同时提供已发生原作节点和未来时间锁。未来人物去向、年龄、实力与事件结果不得提前出现在正文中。
- 全局偏差值不能单独改写原作。只有玩家亲自接触相关人物、势力或地点后留下的因果记录，才能参与对应历史节点的抗性判定。

## DeepSeek 首版接入

- 采用玩家自备 API Key。
- 使用 OpenAI 兼容接口，Base URL 为 `https://api.deepseek.com`。
- 当前官方模型为 `deepseek-v4-flash` 与 `deepseek-v4-pro`；旧的 `deepseek-chat`、`deepseek-reasoner` 别名已进入弃用安排。
- 两个当前模型均支持 JSON Output、工具调用和 1M 上下文。
- 建议默认使用 Flash 处理日常叙事，在关键剧情规划、复杂 NPC 决策或一致性修复时按需使用 Pro；最终策略待测试成本和质量后确认。
- DeepSeek 上下文缓存默认开启。系统提示词、固定世界规则和稳定角色资料应保持前缀一致，以提高缓存命中率。

## 长篇向量记忆

- SQLite `vector_memories` 保存384维本地混合向量，不引入独立向量服务。
- 每次行动提交时把玩家行动、程序结果、日期、地点和正文在同一事务内索引；每个存档最多2,000条。
- 生成正文前用当前行动、任务、地点和在场人物组成查询，按余弦相似度、重要性与新近度召回Top 8。
- 旧存档自动从玩家可知的行动账本、关键选择、NPC互动和情报回填；回溯按行动序号隔离未来分支。
- 当前实现是零依赖中文特征哈希向量，未来可替换为本地 `bge-m3` 或兼容 embeddings API，接口与SQLite数据层保持不变。
- 独立 `canon_knowledge_vectors` 保存概括化的斗罗人物性格、阶段时间线、关键关系、势力、地点、事件和魂兽生态；按当前时代、年份、已知人物与已发现地点过滤后 Top 10 召回。
- `world_logic_vectors` 保存原创世界运行规律和异常反应链，按时代 Top 8 召回；与原著事实分表，避免把游戏模拟规则冒充原著设定。
- 全局原著知识只提供历史与行为惯性；玩家存档中的关系、资源、职位、伤势和因果足迹始终拥有更高事实优先级。

## API Key 安全待定项

浏览器页面无法真正安全地长期保存第三方 API Key。首版需要在“本地网页应用”和“公网托管网站”之间做选择，再决定使用本地后端、安全代理或仅会话内保存等方案。

## 已选择的本地技术形态

第一版作为本地网页应用运行：

- 前端建议采用 React + TypeScript + Vite。
- 本地服务采用 Node.js + TypeScript，负责 DeepSeek 请求、规则计算和存档访问。
- 世界状态使用 SQLite 保存，重要变化追加到不可变事件日志中。
- API Key 只交给本地服务，绝不写入 Git、存档或浏览器可同步数据；开发阶段优先从本地环境变量或忽略的私有配置读取。
- 浏览器只连接 `localhost`，不直接持有长期 API Key。
- 未来 Godot 版本继续复用规则数据结构、存档 schema 和 DeepSeek 编排协议。
