# 本地向量记忆库

## 目标

长篇行动不能依赖把完整聊天历史反复塞给模型。本项目使用 SQLite 表 `memory_chapters` 保存章节级索引，使用 `vector_memories` 保存玩家已知的具体场景。每次生成正文前先召回最多 3 个相关章节，再从候选章节中召回最多 8 条相关旧事。

人物性格、人生时间线、关键关系、势力、地点、原著事件和魂兽生态使用独立的 `canon_knowledge_vectors` 全局知识层，每回合最多召回 10 条；地点和势力的原著、原著归纳、原创来源随召回结果进入模型，游戏估算路程不进入原著文本。人物资料按年份与日序切成当前公开姓名、目标、势力和已证实力片段，不把最终姓名、终身目标、后来关系或未来势力混入早期上下文。世界基本逻辑另存于 `world_logic_vectors`，每回合最多召回 8 条。设计与知识边界见 `canon-knowledge-vector.md`。

## 当前实现

- 384 维本地混合向量：中文字符一至三元特征哈希，并补充猎魂、修炼、关系、势力、战斗、经济、身份、调查、旅行和后世技术语义组。
- 向量以 `Float32` BLOB 保存在现有 `.data/douluo.db`，不需要额外服务、云端 embedding Key 或模型下载。
- 相似度由向量余弦、记忆重要性和行动新近度共同计算。
- 章节摘要只由已经提交的玩家行动账本与程序结果组成，不采纳隐藏世界状态，也不让模型自行补写章节事实。
- 二阶段检索先用章节标题与章节摘要选出最多 3 个范围，再在范围内对行动、关键选择和连续性场景排名；NPC记忆和玩家已知情报仍可跨章节直接召回。
- 每个存档最多保留 2,000 条，优先保留高重要度和较新的记忆。
- 每次已提交行动会在同一数据库事务内写入行动、程序结果、地点、日期和已生成场景。
- 旧存档首次检索时会从行动账本、关键选择、NPC 已知互动和玩家情报自动回填。
- 回溯后只检索 `action_index <= 当前行动` 的记录；同一行动序号走出新分支时覆盖旧分支向量。

## 信息边界

向量库只能写入玩家公开视图、行动账本、已知情报、长期摘要和 NPC 已经记录的互动。隐藏武魂、未发生事件、玩家未知的秘密旧事、NPC 私有知识与隐藏世界状态不得进入检索文本。原著事件即使已在隐藏世界发生，也必须先成为玩家新闻或可靠情报才能召回；只输入一个尚未知晓的势力名称不能反向解锁该势力。召回结果只作为旧事证据，冲突时当前结构化状态和程序结算优先。

## 上下文预算

- 最近正文：12 段降为 6 段，每段最多 1,600 字。
- 长期摘要：注入上限 1,800 字。
- 普通 NPC 记忆：每人 8 条降为 4 条。
- 玩家情报：20 条降为 12 条。
- 向量召回：每回合 Top 8。
- 章节召回：每回合 Top 3，再执行场景 Top 8。
- 行动语义整理器同样使用 Top 8 旧事消解“他、那里、上次承诺”等指代，但不得据此新增当前权限、资源或结果。
- 正文生成的三层检索是硬门禁而非静默降级；世界逻辑为空或检索失败时不会调用模型。`context_retrievals` 记录每次实际注入数量、命中章节数和经过截断的记忆/原著/逻辑标签，设置页可展开核对，不保存完整提示词或生成正文。

## 局限与升级路线

当前向量器适合本地零依赖运行，中文同词、近义领域和角色/地点复现效果稳定，但不等价于大型神经 embedding 模型。旧存档首次检索会把已有行动账本安全回填为一个章节范围；后续章节变化才会形成更细的索引。未来如果提供本地 `bge-m3` 或兼容 embeddings API，可保持 SQLite 表和检索接口不变，只升级向量生成器并给记录增加 embedding 版本迁移。
