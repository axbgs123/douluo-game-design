# 《斗罗大陆》文字人生模拟游戏：MVP GDD

## 1. 产品定义

一款本地运行、单人游玩的网页文字游戏。玩家扮演随机生成的原创人类角色，在《斗罗大陆》第一部世界架构中以第一人称自由行动。程序负责世界状态与因果结算，DeepSeek 负责把结果写成连贯小说并表演 NPC。

首版追求的体验不是复刻唐三剧情，而是：在可信的斗罗世界里得到一个只属于玩家的人生开局，发现武魂与隐藏出身，做出选择，承担代价，并完成第一次真正改变成长路线的猎魂。

### 文字游戏优先原则

- 正文阅读与自然语言输入构成绝大多数游玩时间，是推进世界的主要入口。
- 属性、地图、任务、背包和关系面板只用于查阅与辅助决策，不能取代小说叙事。
- 战斗、旅行、觉醒和猎魂以交互小说形式展开，不在 MVP 中制作地图走格、卡牌战斗或动作小游戏。
- 精确数值仅在原作明确使用的魂力等级等位置显示，其余状态优先写成普通、优秀、顶尖、轻伤、危险等自然语言描述。
- AI 文本必须保持前后连续、人物动机可信和第一人称代入感，不能退化成连续的系统日志或数值播报。

## 2. 运行与技术边界

- 本地网页应用，首选 React、TypeScript 与 Vite。
- 本地 Node.js/TypeScript 服务负责规则、存档和 API 代理。
- SQLite 保存世界真相、角色已知信息和事件日志。
- 玩家填写自己的 DeepSeek API Key；密钥只保存在本机服务端配置中。
- 纯单机，不制作多人同步、账号、云存档和排行榜。
- MVP 不依赖美术；网页版成熟后再考虑 Godot 封装和美术化。

## 3. MVP 起止范围

### 起点

1. 玩家选择性别；首版种族固定为人类。
2. 玩家填写约 5 个性格关键词并回答约 8 道情境题。
3. 系统按随机种子生成三名候选人，显示时代关系、出生地点、出身和先天征兆，不显示武魂、金手指和隐藏风险。
4. 玩家可以无限重抽，选中后进入角色人生。
5. 玩家亲历武魂觉醒，规则层生成觉醒结果，AI 负责场景与人物反应。

### 终点

玩家完成第一次猎魂的调查、准备、旅行、追踪、战斗、吸收和后果七阶段，安全或带伤返回聚居地。系统保存魂环、魂技、消耗、伤势、关系、承诺、世界时间和所有蝴蝶效应。本次返回构成首个原型的完整通关点，但角色存档可继续保留。

## 4. 核心循环

```text
读取处境与已知信息
        ↓
玩家输入行动和对白
        ↓
规则层判断可行过程、时间、成本、风险与结果
        ↓
AI 将确定结果写成第一人称小说，并生成三个情境建议
        ↓
玩家接受建议或自由输入其他尝试
        ↓
NPC、任务、关系、地图和历史在后台继续演化
```

玩家可以尝试不可能或极不理智的行动。系统不静默改写输入，而是让尝试失败并结算时间、暴露、资源、伤势、关系甚至死亡。

## 5. 叙事与规则权责

### 程序最终决定

- 随机生成结果、属性、魂力、武魂、时间、位置和资源。
- 战斗胜负、伤势、死亡、掉落、魂环适配与吸收结果。
- NPC 行动、关系变化、任务事实、历史锚点与世界偏差。
- 所有持久状态修改以及角色知道哪些信息。

### AI 最终决定

- 第一人称正文、对白、气氛、战术解释和非关键细节。
- 根据处境、原著背景、角色性格和既往行为生成三个建议行动。
- 将规则结果自然地表达出来，但不能追加奖励、改变胜负或泄露隐藏数据。

## 6. 世界与原著边界

- 第一部时代资料是 MVP 唯一正式入口，但出生年代可覆盖第一部涉及的历史范围。
- 原著人物、势力、资源、材料生态和历史拥有不同等级的原作惯性，没有不可突破的剧情护盾。
- 玩家本人不受“约 10% 偏差”限制；玩家造成的世界变化必须有完整因果。
- NPC 在玩家视野外继续训练、移动、交往、争斗、受伤和死亡。
- 偏远角色可能长期无法接触唐三或原著主线。

## 7. 随机出身与跨界内容

- 斗罗本地人、穿越者、失忆者、系统持有者、原创外部世界来客等均可生成。
- 外部方向以中国神话、洪荒、修仙作品设定和 AI 原创世界为主，不加入动漫或二次元内容包。
- 小说内容只借用体质、功法、器物和力量结构，不让小说人物本人穿越；神话与洪荒人物可以在强约束下出现。
- 所有金手指都必须成长，不能开局完整碾压世界。
- 极低概率允许多个相容体系；冲突、资源竞争和隐藏代价在生成时锁定。
- 玩家不能返回外部世界。

## 8. 人格系统

- 初始人格来自关键词和情境题，而不是职业式固定选项。
- 行为证据持续修正勇敢、谨慎、守信、功利、同理心、权威态度等内部倾向。
- 人格影响内心文本、建议行动、意志判定、NPC 印象、修炼效率和能力成长。
- 玩家始终可以违背性格；反复违背会改变人格，过渡期可能产生心理压力或意志消耗。

## 9. 时间、任务与自由行动

- 单局标准目标约 10 小时，高速模式可将同等世界过程压缩至约 1–2 小时。
- 高速只压缩文字与操作，不改变真实概率和因果。
- 玩家可快进一天、一个月或一年；遇到重大风险、突破、袭击、关键关系变化或历史事件时自动中断。
- 任务面板只记录承诺、悬赏、线索、修炼需求、人生计划和可能后果。
- 奖励只来自事件本身，不存在统一的“完成任务凭空发奖”。

## 10. 第一次猎魂

每次猎魂都使用七阶段流程，详见 `soul-hunting-system.md`。MVP 至少要支持：

- 导师、宗门、同伴或系统给出带来源的候选推荐。
- 推荐可能不完整、过时、有偏见或恶意；高知识者可预测大致年限和可能魂技方向。
- 玩家自行选择目标、准备队伍与物资，也可以拒绝推荐。
- 队友可控制、削弱、治疗和救援，吸收者必须完成最后一击。
- 传统猎杀是基础路线；契约、自愿献环、自凝魂环由相应设定解锁。
- 吸收默认只能由本人承受；特殊外力介入必须由既有规则明确支持。
- 失败可导致疲劳、伤势、永久伤残、武魂受损、魂力倒退或死亡。

## 11. 难度

五档为：爽、简单、标准、困难、地狱。

- 难度改变资源压力、情报透明度、风险修正、NPC 决策水平、失败后果和局外倍率。
- 难度不推翻世界因果；低难度的自杀式行为仍可能死亡，高难度的充分准备不会被强制判败。
- 魂环吸收的具体差异见 `soul-hunting-system.md`。

## 12. 界面

主界面常驻：小说正文、自由输入框、三个建议行动、人物属性、武魂/魂技、背包、地图、关系、任务和世界时间。

辅助界面：存档/读档、历史正文、系统事件日志、通知、速度、难度、API 设置和调试模式。原作偏差、随机种子与隐藏判定只在调试模式显示。

布局上正文与输入区域拥有最高视觉权重，辅助面板默认折叠或置于侧栏。玩家不打开任何辅助面板，也应能仅靠正文、输入框和建议行动完成主流程。

## 13. MVP 验收标准

- 同一随机种子能够复现候选角色和所有程序随机结果。
- 候选卡不泄露武魂和隐藏金手指，选中后能完整经历觉醒。
- 自由输入可以驱动行动与对白，不要求点击预设建议。
- 玩家仅阅读正文并使用自由输入或建议行动，就能完成整个 MVP，不被迫操作复杂面板或小游戏。
- AI 无法绕过规则层修改魂力、物品、时间、关系、伤势和魂环。
- NPC 与世界时间会在玩家行动及快进时继续变化。
- 存档、退出和重新载入后，世界真相、角色已知信息和正文历史一致。
- 能完整游玩第一次猎魂七阶段，并支持成功、受伤、失败和死亡等不同结局。
- 吸收成功后生成合法魂技并保存所有后果；返回聚居地后形成可继续游玩的角色存档。
- DeepSeek 调用失败、超时或返回非法结构时不会损坏存档，并允许重试。

## 14. MVP 暂不实现

- 第二至第五部正式入口。
- 第一部完整终局、成神和跨时代连续世界推演的可玩实现。
- 多人、联网世界、云账号和作者统一承担 API 费用。
- Godot 封装、角色立绘、地图美术、动画和音效。

这些内容保留在长期架构中，但不能阻塞第一个猎魂闭环上线。
