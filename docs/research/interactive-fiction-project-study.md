# 互动小说与斗罗同类项目调研台账

更新日期：2026-08-24

## 范围与方法

本轮只研究公开仓库、项目官方文档和用户已授权的本地资料。公开来源用于学习机制；本地四部小说只用于事实核对，不进入 Git，也不复制原文。项目有明确开源许可证时仍只借鉴架构思想；无许可证或许可证不明的仓库不复制代码、文本、美术和数据。

检索结果中，直接以斗罗为主题且有较完整工程说明的项目很少；因此分成“同题材玩法”与“同类型 AI 互动叙事引擎”两组比较。

## 形成的实现原则

1. 程序是事实裁判，模型只负责行动语义与小说表达。所有资源、战斗、移动、关系和原作偏移先由规则结算。
2. 记忆必须回答“谁亲历、何时发生、是否仍有效、重要程度多高”，不能只保存一句不可追溯的摘要。
3. 原作知识按当前地点、人物、时代、行动和玩家知情边界检索，并有固定字符预算；未来事件永远先过滤再入 prompt。
4. 每个关键节点拥有稳定 ID、进入条件、访问次数、介入状态和因果足迹；自由输入只决定如何接近或改变节点。
5. 玩家能看到规则收据、未决承诺和世界连续性摘要，但看不到角色尚未知晓的后台事实。
6. 每项模型能力都必须有无需付费 API 的结构测试/回放测试；真实模型只做小样本验收。

## 第一批落地顺序

1. 场景知识检索预算与别名匹配。
2. NPC 结构化情节记忆（见证者、显著度、年份/日、来源行动），同时兼容旧存档。
3. 关键节点访问/介入记录与玩家可见的规则收据。
4. 20 回合固定长局回放、叙事—状态矛盾检查和提示词预算测试。
5. 将同一套内容 schema 扩展到斗二、斗三、斗四，而不是复制四套分叉代码。

## 反向审查

- 不采用“让模型输出 `[ITEM_ADD]` 就直接修改库存”的方案：它会把事实控制权交回模型，与当前规则优先架构冲突。
- 暂不采用多代理并发：会显著增加成本、延迟、部分失败与调试复杂度，且 5 元预算不足以证明收益。
- 暂不采用 Neo4j：现有 SQLite 与内存世界模型足以支持斗一；先证明关系检索规模确有瓶颈。
- 不复制未授权斗罗仓库的知识库、数值、美术或叙事文本；同题材仓库只作为功能覆盖与工程流程参照。
