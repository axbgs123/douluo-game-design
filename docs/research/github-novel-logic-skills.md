# GitHub 小说逻辑 Skill 审计与游戏适配

更新时间：2026-08-24。

## 目标

寻找专门增强小说因果、人物知情、时间线、资源状态和多人场景连续性的 GitHub Skill，并把可验证机制接入《未定之书》的 AI 正文生成前，而不是增加一个只在提示词里“注意逻辑”的口号。

## 采用来源

来源：<https://github.com/lq252392/writing-with-ai-agents/tree/master/.agents/skills/novel-continuity-review>
核验提交：`f3f2df6db31bda8bd5363187d3d4c28dd87d1eed`

有价值的机制：状态版本与约束版本必须匹配；检查人物认知、时间顺序、规则边界、在场人数和版本一致性；多人场景不能在中段悄悄塌缩成双人对白；问题应给证据和最小修订。

边界：该提交未发现明确 LICENSE 文件，因此项目不复制其 Skill 文本或代码，只重新实现通用检查思想。

适配方式：没有引入上游 Python CLI、外部模型接口、项目模板或自动改稿，而是在 `server/domain/story-rules.ts` 中用现有结构化存档重新实现 TypeScript 逻辑合同。

## 运行时实现

`narrative-logic.v1` 在程序结算之后、DeepSeek 正文请求之前生成：

1. 状态版本与约束版本。
2. 时代、日期、地点、公开身份、公开/隐藏武魂和玩家原作因果足迹。
3. 主角欲望、可用信息及来源、权限、资源、程序动作和固定后果。
4. 参与者的独立目标、亲历/转述信息、知识上限、权限和反应义务。
5. 目击者、权限人、利益、异常事件立即反应和应留下的痕迹。
6. 多人场景不得塌缩的规模合同。
7. 必须改变的时间、资源、关系、情报、风险或成长状态，以及绝对禁止模型发明的事项。

逻辑包缺关键字段时抛出 `NarrativeLogicPreflightError`，请求不会进入模型，也不会把同一个确定性错误重复生成四次。通过后，逻辑包随场景知识和固定规则结果一起发送给叙事器；正文生成后仍执行年代、信息边界、程序结果和语言审校。

## 没有直接安装的原因

- 游戏已经拥有 SQLite 存档和结构化世界状态，另建 Markdown 真源会产生双真源冲突。
- 上游通用小说 Skill 不知道斗一至斗四的年代隔离、魂力资源、隐藏武魂和程序胜负。
- 独立 Python 审稿只能在生成后发现问题；本项目需要在付费模型调用前拦住缺失的逻辑前提。
- 自动改稿或全章重写不能获得修改规则结果的权限。
